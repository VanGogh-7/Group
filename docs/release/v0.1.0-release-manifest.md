## Credential and evidence handling

- Do not read, print, copy, hash, or otherwise inspect Cargo credential
  contents. The preflight records only availability classification, never a
  credential path or value.
- Do not put a token or other secret in a command line, environment dump, log,
  archive, report, repository file, shell history, or checksum manifest.
- Retain bounded command outcomes, timestamps, response classifications,
  identities, and checksums. Do not retain raw credential-bearing requests,
  headers, or authentication diagnostics.
- Treat registry search/API results as absence or metadata observations only;
  they do not prove ownership, index visibility, resolution, or consumer
  usability.
- Record a partial release as partial and stop at a Human Checkpoint. Never
  retry publication blindly, force a tag or push, yank a version, or skip a
  dependency layer.
- The current host-side preflight records a present, regular, non-symlink
  credential-store candidate with restrictive metadata and no Cargo-home
  provider-config override. This is metadata-only preflight availability, not
  an authentication or ownership test; an authorized operator must repeat the
  audit immediately before publication.
